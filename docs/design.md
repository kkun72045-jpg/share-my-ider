# 实时演算：实现与改进方向

本项目的目标是让“浏览商品 → 看自己穿上的效果”成为可控的实时流程。“实时演算”是项目名称；当前没有提出或验证新的机器学习算法。

## 当前链路

1. 电脑工具栏唤起侧边面板；手机适配包通过扩展菜单唤起 popup。用户点击“选网页图片”后才读取当前页图片元数据；电脑也支持右键选择。随后确认导入或上传本地服装图片。
2. 扩展以最小范围申请该图片来源的权限，下载时不带 Cookie、不带 Referer，不跟随重定向。普通浏览时没有全站内容脚本。
3. 摄像头只在显式点击后启动，音频关闭。此时画面留在本地预览。
4. 用户勾选云端处理确认并开始会话后，扩展向本机服务或用户明确配置的个人 HTTPS 服务请求短期凭证；HTTPS 服务须填写独立访问码并允许该来源网络权限。
5. 本机 broker 使用用户自己的 API 密钥，向 Decart 官方接口签发限模型、限来源、限时凭证。
6. 单独的引擎页面加载官方 MIT SDK，将视频及参考服装提交给实时试衣服务。界面展示远端真实视频与原始视频。
7. 停止时失效所有旧异步操作，卸载引擎页面、断开模型并停止摄像头。晚到的摄像头授权或连接结果不能重新开启当前会话。

拆出独立引擎页面，是为了让连接尚未完成时也能卸载相关执行上下文；不会创建公开代理或使用 Anywear 的私有令牌服务。

## 自主实现与外部依赖

原创部分包括扩展交互、服装输入、界面、状态与资源生命周期、本机 token broker、输入和权限策略、测试与文档。Decart SDK 负责服务连接，Decart 的托管模型负责生成服装与人体的视觉融合。MIT 许可不包括托管模型权重或推理服务。

主密钥仅由服务端读取 `.env`，前端短期凭证和个人服务访问码只放在运行中的内存。面板卸载会丢弃衣橱和临时连接信息。电脑右键选图 URL 在 `chrome.storage.session` 暂存，成功导入后删除；超过 10 分钟的待导入项不再使用。应用没有保存浏览历史或上传额外遥测。

broker 仅绑定回环地址并严格校验扩展/开发页面来源，限制请求体、并发与签发次数。手机适配增加明确列出的扩展来源和独立 Bearer 访问码，须由用户的 HTTPS 反向代理接入，不能直接暴露无认证默认服务。未实现多用户账户、额度和计费系统，也未部署公共服务。

## 手机适配边界

同一面板生成 Firefox Android 和 Safari 源包：移除电脑专用 sidePanel/contextMenus/background，改用 action.default_popup。网页选图采用一次性的 activeTab + scripting。Firefox 包声明视频、认证信息和网页内容传输。平台来源、媒体权限、popup 生命周期和 SDK 连通性仍需各自真机测试；可构建不等于完成兼容性验收。

## 后续改进应如何证明

优先收集经用户同意的受控测试结果：首帧等待时间、稳定输出帧率、切衣响应时间、断线恢复、领口/纹理保留程度，以及停止后的摄像头与连接状态。使用相同设备、网络和服装素材做对照，才能判断是否优于参照产品。

下一阶段可研究：服装前景提取、稳定的参考图预处理、相机姿态提示、提供方适配接口，以及获许可模型的本地/独立托管。没有实现的能力不作为第一版卖点。自研生成模型需要训练数据授权、GPU 预算与系统评测，不能通过换界面或换项目名称获得。
